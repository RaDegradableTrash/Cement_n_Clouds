# Voyage 灰暗分层渲染实施报告

## 范围与版本

保留 Unity 6000.5.7f1 / URP 17.5 与现有 PC Forward+ 路径。没有迁移 HDRP，没有替换角色模型、动画或地形资源。参考图用于提取低饱和环境、冷暖对照、局部受光和可读暗部；测试场景是灯光实验室，不是参考建筑的复刻。

改造前已将现有 snapshot 快进并推送到 GitHub，备份提交为 `95c42cfe9765c184fc6a6d36976e7579414d6722`。本轮仅向 snapshot 提交实验版本，不向 main 发布。远端为 RaDegradableTrash/Cement_n_Clouds（原 Voyage 地址重定向）。

## 使用方式

- 打开主场景 `Assets/Scenes/SampleScene.unity` 后播放，基础风格自动接入原昼夜系统。F7 打开风格面板；手动选择优先于场景配置，Scene default 清除手动选择。
- 打开 `Assets/Scenes/LookDevelopment.unity` 后播放，左上角可切换冷灰暮夜、暖光室内、戏剧化动漫三个区域、实用光源、行走动画，以及捕获 1920×1080 PNG。
- 捕获路径为 `Application.persistentDataPath/LookCaptures`。截图使用完整 URP StandardRequest，包含后处理。
- 三套资产位于 `Assets/Resources/Looks/`。在场景根对象添加 `VoyageLookScene` 并指定 profile，即可设置场景默认值。主场景无专用覆盖时使用 ColdDusk，但曝光与光源仍跟随昼夜。
- 脚本调用 `VoyageLookController.Instance.SetLook(profile, blendSeconds)`；调用 `ClearManualLook(blendSeconds)` 恢复场景/全局默认。默认过渡 0.7 秒，使用平滑插值。
- 菜单 `Voyage/Look Development/Install profiles and studio` 可重新生成预设与实验室。它会重写这些测试资产；已手工调整的预设应另存副本。

## 实现

`VoyageLookProfile` 集中定义曝光、饱和度、对比度、环境响应、阴影色、明暗阈值/柔和度、受光轮廓、高光相关照明、雾色和 Bloom。`VoyageLookController` 管理独立运行时 Volume，使用 ACES、HDR 调色、克制 Bloom 和暗角；普通视角关闭景深和运动模糊。

原 DayNightSystem 仍独占时间、太阳/月亮方向及 RenderSettings；FogSystem 仍独占雾。控制器提供参数，不争夺原系统的逐帧设置。运行时显式刷新环境 SH 探针，避免没有烘焙数据的场景出现环境漫反射缺失；夜间天空、赤道与地面环境颜色统一调整，而非给角色或草地加入固定自发光下限。

角色 shader `Voyage/Character/Layered` 复用 URP Lit 的顶点、法线贴图、透明裁剪、雾、实例化和辅助通道，保留蒙皮与动画。直接光使用可调软硬的漫反射分区、较克制的 PBR 高光，以及受灯光方向、距离和阴影共同限制的轮廓光。阴影、深度、深度法线、Meta 和运动向量通道沿用 URP。12 个现有角色材质已迁移，原材质数据保留。Unity shader 派生代码的许可证一并保留。

草地与地形继续共享 VoyageMeadowLighting；移除固定环境亮度下限，增加 Forward+ 附加灯和阴影变体，并补齐深度法线。PC 管线开启附加灯阴影、2048 阴影图集及 HDR 调色；已有 SSAO 以降采样、低强度运行。

车辆按真实 RV1.0 的 HeadLightL、HeadLightR、HeadLightFix、LightL、LightR 灯具绑定，保留原位置与朝向，由原车灯开关控制。三个主要车灯投影，辅助灯不投影；阅读灯和制动灯保持独立。

测试区域包含深色/浅色/金属材质球、粗糙墙面、带法线的湿润地面、窗框投影和局部反射探针。未烘焙实验室以宽范围低强度补光近似反射光，补光与实用灯开关分离。

## 复现与验证方法

Editor 批处理入口：`VoyageLookReview.StudioIteration` 重建并检查实验室；`VoyageLookReview.TestScene` 仅检查现有实验室；`VoyageLookReview.MainScene` 检查主场景。输出位于 `Logs/LookReview/`。命令使用 `-batchmode -projectPath <项目绝对路径> -executeMethod <入口> -logFile <日志>`，脚本完成后自行退出，不能同时打开同一项目的另一个 Unity 实例。

`VoyageLookReview.Baseline` 只设置捕获标签，必须在改造前源码状态下运行才是真实基线，不能把改造后的画面标作 before。本轮原始基线通过临时恢复备份源码生成，完成后恢复全部实施文件。

固定随机种子 1741，主场景时刻 12:00 / 17:30 / 22:00，实验室 22:00；冻结车辆刚体，使用固定机位，另检查平移机位及行走采样。运行检查覆盖预设优先级、清除手动预设与场景重载。截图不是生成图，也没有在 Unity 外调色。

## 已知边界

现有人物是没有精细五官贴图的低多边形模板；渲染改造不会生成参考图中的眼睛、发丝和服装细节。参考中的复杂城市反射、积雪和精细建筑不在本轮资产范围内。湿润地面采用现有 URP 反射探针，并非屏幕空间反射。

性能采样在 RTX 5070 Laptop GPU、1920×1080 Editor Play Mode 中进行，每个视角预热 30 个实际渲染帧，采样 120 帧，包含同步 GPU 回读成本。它用于比较渲染预算，不等同独立 Player 的持续 60 FPS 或完整游戏帧耗时。不得据此声称独立运行性能已验收。

Unity 6000.5.7f1 的 SearchDatabase 启动索引在本工作树出现 ArgumentOutOfRangeException；该编辑器问题也出现在原始基线，单独记录，不把它当作 shader 编译成功或失败的依据。

## 最后一轮暗部修正

只对角色的间接漫反射反照率做 45% 平方根压缩，保留直接光、镜面高光和贴图的原始响应。深色布料因此能保留少量折面变化，浅色衬衫不会随之整体过曝。该处理仍乘以实际环境光，完全无光时不会自发光。它属于风格化材质响应，不是物理准确的能量模型。
